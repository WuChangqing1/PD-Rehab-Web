## 脚本和环境

- `scripts/training-face-staging.sh`：准备并运行独立预发布，端口 `127.0.0.1:18193`。模型文件和现有 Python 只读复用；预发布数据库、上传目录和密钥单独存放。脚本使用的 FFmpeg 4.4.2 包解在 staging 目录，未安装到系统。预发布用户服务上限为 1200 MiB 和 80% CPU。
- `scripts/training-face-staging-app.py`：预发布 Web 静态页面入口，不进入生产服务。开发机可用 `ssh -N -L 18193:127.0.0.1:18193 fengz` 后访问本机预发布页面。
- `scripts/training-face-staging-smoke.py` 和 `scripts/training-face-staging-browser.mjs`：只对该预发布端口验收。账号、令牌运行时注入；不从生产取数据。
- 停止预发布可执行 `systemctl --user stop pd-training-face-staging-20261104`，不需要停止生产服务。

## 待批准的生产变更与回滚

正式上线前，先补齐 Android 真机签收及 23 项原始失败清单。之后请审核以下具体变更：

1. 备份生产 SQLite（使用 SQLite 在线备份机制，记录迁移版本、数据库完整性和 SHA-256），保存现有前端静态发布、环境配置和后端提交。发布窗口内先停新增录像流量；若生产仍处于本报告的旧版本，则没有新增录像流量可停止。
2. 在 PD 服务专用目录交付 FFmpeg/ffprobe（避免影响其他项目），由服务用户验证 H.264；核对真实模型、磁盘、队列限制及单 worker。沿用现有 HTTPS 路由，核对至少可接收 4 MiB 的分块。若确需修改 Nginx，另行纳入批准范围。
3. 在明确的维护窗口，仅对 PD 生产数据库执行 `k7f9a1b3c5d7 → l8a0b2c4d6e8`，发布同一提交的 Web 与后端，启用 `TRAINING_VIDEO_ENABLED=true`，仅重启 PD 后端。校验能力、登录、患者权限、旧训练/计划/AI 接口和一条专用测试档案闭环。
4. 失败时先停收新录像，按状态处理已有任务，再恢复旧 Web 静态包、旧后端及配置，仅重启 PD。默认**保留**加法迁移表及新数据，不运行破坏性的 downgrade，也不直接覆盖仍有业务写入的数据库。若确需数据库恢复，必须先保全上线后写入、核对可恢复范围并另行批准；留存加密备份和恢复记录。
