# Web 实时语音输入实现计划

Goal: 按用户选择使用国内流式 ASR API，替换录音回听，边说边出字并可编辑发送。
Architecture: 浏览器 AudioWorklet 生成16kHz单声道PCM，通过同源WebSocket发送给FastAPI；后端使用百炼Fun-ASR-Realtime WebSocket协议转发音频并回传文本，不落盘、不把密钥发给前端。首次连接使用REST签发的一次性短期票据，严格同源及实时账号校验。
Spec: 本聊天用户2026-11-23选择API方式及先普通话、重庆/四川话的识别目标。

- [x] 安全边界及协议测试：未配置、同源、一次性票据、账号撤销、限流、PCM大小/时长、供应商启动/完成/失败、静态密钥不得外泄。
- [x] 实现后端开关、百炼适配器和流式路由；保持GLM/模型、患者、训练和数据库不变。
- [x] 实现有状态PCM编码与AudioWorklet采集；输入框文本增量替换、停止确认、取消还原、迟到授权、退出清理和防重复。
- [x] 替换VoiceInput录音/回听为点麦克风说话，输入框回填并禁用正在识别时的发送，支持中英文。
- [x] 配置脚本使用getpass安全输入Key和控制台地址，默认写入被Git忽略的专用配置文件；提供开通、部署和验收说明。
- [x] 全部前端测试、双base构建、相关pytest和真实浏览器验证；真实识别仍需用户开通并安全配置Key后验收，不用替身冒充。

Constraints: 不使用浏览器自带厂商不明的SpeechRecognition；不新增模型权重；不保存语音文件；音频仅在明确点击语音输入时传给ASR；不自动发送文本给GLM；本轮先本地实现，不自动覆盖线上。
