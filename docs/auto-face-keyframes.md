# 面部视频自动选帧：本地实现与验证结果

更新：2026-11-01。本文件记录功能提交 2010f12 的本地验收，不是实时发布状态；后续发布沿用这里的人工确认与算法边界。

## 实际交互

1. 评估中心进入面部表现分析，确认患者。
2. 网页录制后停止，或选择一个已有视频。
3. 系统自动查找完整面部变化；查找期间禁止开始分析。
4. 一段候选时显示“开始 / 变化最明显 / 结束”三个预览；多段候选时先选择其中一段。
5. 操作者点击“确认使用此片段”，才可开始分析。
6. 通过现有 CausalNet 权重分类，保存并回读结果。
7. 找不到可靠片段时重录，或打开“手动选帧（医生）”。原始帧号不再默认显示。

当前保留人工确认，不能称为经过验证的全自动微表情系统。录制摄像头的物理设备与权限需在使用设备上另行检查；本轮实际浏览器链路采用本地文件上传。

## 当前算法究竟是什么

当前自动选帧为独立实现的 face-displacement-multiscale-v1 短片基线，不是 DMA 论文代码的完整复现，也没有替换分类权重。

- MediaPipe FaceMesh 获取面部关键点，用眼角及鼻部稳定锚点做相似变换，移除平移、平面旋转和尺度变化。
- 以初始约 0.3 秒的中位关键点作为参考，计算嘴部与眉部位移，并按眼间距归一化；排除直接的眼睑区域。
- 使用中值滤波、噪声基线和完整位移变化区间寻找候选；缺少平稳起点或终点时不补造边界。
- 峰值使用位移高平台中部，而不是相邻帧运动速度最大处。
- 输出多时间尺度的局部对比诊断量；这些是工程诊断，不是校准置信度，也不冒充 DMA 的原始投票输出。
- 头动检查同时观察整段残差与短时持续残差，避免短暂转头被整段百分位掩盖。
- 全部帧号保持原始视频的 1 基索引，时间来自实际解码。自动定位至多处理约 30 秒、原始 1800 帧的短片；跟踪最多约 30 FPS，不插帧或伪改采集 FPS。
- 区间和峰值均为候选。一个片段内的多个变化不自动强行合并，也不通过最终分类分数反向挑选“最好看”的结果。

初始自然状态、0.018 的归一化位移阈值及噪声倍数都是工程起点，尚无跨人群标定。尤其不能保证已排除所有眨眼、透视头动或照明干扰。

CausalNet 的 TV-L1、光学应变、四路特征和 s12.pth 严格权重加载路径保持不变。分类输出仍为负向 / 正向 / 惊讶，不输出患病概率。

## 研究来源与真实对照

| 来源 | 固定版本 | 本次用途 |
| --- | --- | --- |
| [DMA-ME-Spotting](https://github.com/TJUMMG/DMA-ME-Spotting) | a1c80ee4ff2bae91ccd313f142d9e73ac658f10b | 阅读多尺度窗口、峰值邻域和完整区间生成思想；未声称跑通作者数据集实验 |
| [SoftNet-SpotME](https://github.com/genbing99/SoftNet-SpotME) | dd43d1e1d5ae471998ceb3be3177e2d9517c58fd | 实际运行作者网络、公开 CASME_sq 权重和光流预处理，作离线技术对照 |

SoftNet 使用公开 s1.hdf5；它是一次折权重兼容性试验，不是针对该手机录像选择的最优权重。现有 TensorFlow 2.16.1 环境通过加载；为兼容新接口，仅将 pandas 的 ffill 改为 axis 关键字、SGD 的 lr 改为 learning_rate。单视频包装器还负责手机方向校正、将输入最长边缩到 640、按首帧固定人脸框裁为 128×128，再调用作者特征预处理。上述适配不能等同于论文实验的严格复现。

| 方法 | 在同一原始录像中得到的位置 |
| --- | --- |
| 本次位移基线 | 101 / 115 / 223 |
| 此前手动技术选帧 | 31 / 121 / 211 |
| SoftNet micro，k=6 | 128 / 134 / 140；214 / 220 / 226 |
| SoftNet macro，k=18 | 85 / 103 / 121；199 / 217 / 235 |

SoftNet 中间列是定位分数的峰，不应直接当成人工标注的真实 apex。两种公开权重各输出了两个候选，不能据此声称谁更准确。此前的手动三帧也不是独立专家真值。当前基线峰值与此前手选相差约 0.2 秒，而起始位置差异明显；这正是保留人工确认的原因。

## 真实权重运行结果

- 原始录像约 8.73 秒、262 帧、30.006 FPS，未经插帧。
- 自动 101 / 115 / 223 -> 真实 CausalNet 推理 -> 数据库保存 -> API 回读通过。
- 最终本地整条接口检查约 41.8 秒，包括原始 4K 文件自动定位、分类、保存和额外的无写入/篡改拒绝检查；不是纯推理耗时，也不是线上性能承诺。
- 该三帧得到正向类别，分数约为：负向 0.02187、正向 0.97277、惊讶 0.00536。数值只是模型相对分数，不是已校准准确率。
- 浏览器另用仅本地保存、H.264 编码的小体积录像副本，实测三个预览、确认前禁用、确认后实际分析和结果更新。
- 所有录像、脸部截图、完整原始输出和第三方权重均在忽略目录，不纳入 Git。

## 安全与状态处理

新增 POST /api/micro-expression/keyframes 为已登录临时选帧接口，不创建患者评估、媒体或结果记录。文件流式写入临时目录，检查扩展名和大小，成功/异常都清理。

选择请求在原隔离 worker 内按模型锁串行运行，不把 Torch 或旧 MediaPipe 引入 Web 解释器。分类仍接受原手动帧号。

每个自动候选带短期签名，绑定实际视频 SHA256、帧号、当前操作者、算法版本和过期时间。分析时重新核对；改帧、换视频、换账号或过期均不能继续使用原自动来源。签名证明候选来源与输入一致，不证明临床正确或操作者实际作出了专业判断。

结果沿用现有 quality_json，新增 keyframe_selection 来源；无数据库迁移。客户端修改帧号后只能重新确认自动候选或显式改用手动来源。录制、换视频、换患者、重试和过期响应均会使旧确认失效。

录制回调含生命周期版本保护，组件销毁、丢弃录制或另一段采集开始后，旧 onstop 不会恢复被清除的视频。

## 测试与实际边界

- 后端全量：514 passed，2 skipped。跳过项均是隔离工作区未包含旧 MicroFlow 私有源码的测试；当前 CausalNet 真实权重另行实跑。
- 前端：317 passed；根路径与 /pd-rehab/ 构建通过。
- 静止画面、整幅平移、无人脸三个实际视频流水线反例均不产生候选。
- 关键点级测试覆盖眼睑变化不进入表情位移、刚性变换移除；不代表已穷尽真实眨眼或头动。
- 回归覆盖：短暂高残差头动、旧录制销毁后回调、未结束动作、多个区间、位移平台峰值、旧响应与确认失效、鉴权、无写入临时接口及签名边界。
- 桌面、768 像素平板和 390 像素手机浏览器检查；平板和手机无横向溢出；中文和英文候选界面可用。属于浏览器视口验证，不是所有真机兼容性验证。不可播放编码的错误提示、确认禁用、手动回退及重新采集清空状态也已实际检查。
- 代码独立审查发现的两个重要问题已用失败复现测试修复：延迟录制回调和短时头动漏检。

## 仍需完成的独立效果评估

目前只有一段用户真实录像和少量技术反例，不能给出定位准确率、分类准确率、跨人泛化或临床效果结论。

正式开放无需确认的自动分析前，需要：
1. 收集多人、多设备、不同光照的短片，以及完整变化、未结束动作、眨眼、说话、头动、遮挡、无人脸等负例。
2. 由至少两位标注者独立标注起始、峰值和结束，不使用算法输出作为真值；记录分歧。
3. 按人划分调参与独立测试，提前固定阈值和匹配规则。
4. 分别报告区间 IoU / precision / recall、峰值时间误差、无效输入误接收率和拒绝率、耗时与内存。
5. 在有独立类别标签的样本上，比较人工选帧和自动选帧对最终分类的影响；引导表情和自发表情分开报告。

本次实现为可运行、可人工确认的自动选帧流程。发布时应保持同样的确认门限，并另行检查服务器环境、资源完整性及两个访问入口。
