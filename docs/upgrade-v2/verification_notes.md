# 验证方法学笔记 —— 我的工具三次"说谎"

日期：2026-10-12
适用：任何对本项目做浏览器验证的人（首先是我自己）

---

## 为什么写这个

在连续三轮里，**我的验证工具三次产出了"看起来很像缺陷"的假象**，
而每一次我都几乎把它写进报告。

**假缺陷比真缺陷更危险。** 真缺陷会让软件坏掉，假缺陷会让我写出一份
**自信而错误**的报告——而报告是别人决策的依据。

三次都记在下面，因为它们有共同的成因。

---

## 案例一：验证服务器只反代了 `/api`

**现象**：生产构建加载后，工作台与患者档案页抛出 `TypeError`，
页面显示「无法加载工作台数据。」——看起来就是**生产构建崩了**。

**真相**：`API_BASE = BASE_URL + '/api'`，子路径构建调用的是 `/pd-rehab/api`。
我的临时服务器只反代了 `/api`，于是那些请求落到 SPA 回退上，
**以 200 返回了 HTML**。前端拿 HTML 当 JSON 解析，自然炸。

**破绽**：接口响应的 `content-type` 是 `text/html`。
**一个 API 调用如果返回 HTML，就说明它根本没到后端。**

---

## 案例二：glob 模式 `**/api/**` 拦住了应用自己的源码

**现象**：后端不可达时，**7 个页面全部白屏，0 个字符**，`#app` 的 innerHTML 长度为 0，
`__vue_app__` 不存在——看起来就是**后端一死整个应用崩掉**。

**真相**：`**/api/**` **同时匹配**应用自己的源码模块 `/src/api/client.ts`、`/src/api/index.ts`。
我拦掉的是应用程序代码本身。

**破绽**：**连公开路由（`/login`）都渲染不出来**。
应用挂载失败不该和登录状态有关；`/login` 不依赖任何接口。

**真实行为是好的**：完整外壳、取不到的数值显示 `—` 而不是 `0`、明确的提示文案。

---

## 案例三：用 JS 点击隐藏元素

**现象**：按钮审计报告「患者档案的『详情』按钮报错 `Missing required param "id"`」
「康复训练的『进入钢琴训练』按钮 404」——看起来是两个**无效入口**。

**真相**：我用 `page.evaluate(() => el.click())` 按**下标**点击元素。
JS 的 `click()` **不检查可见性**，所以它点到了**手机端专用的隐藏副本**
（`.mobile-only` 卡片在 1440px 下不可见），行上下文不对，于是报错。

用 Playwright 的可见性感知定位器重点：两个按钮都**正常导航**，
0 个错误、0 个失败请求。

**破绽**：**Playwright 拒绝点击不可见元素，而我绕过了它。**
它拒绝，是在帮我。

---

## 共同成因

| 案例 | 我做了什么 | 本该怎么做 |
| --- | --- | --- |
| 一 | 验证服务器与 nginx 行为不一致 | 验证服务器必须**镜像生产**的三件事：静态、SPA 回退、API 反代（含前缀） |
| 二 | 拦截模式写得太宽 | 拦截模式**锚定到 origin**（`http://host:port/api/**`），不要用裸 glob |
| 三 | 用 JS 按下标点击 | **只用可见性感知的定位器**（Playwright 的 `:visible` / `getByRole`） |

**一句话**：**每当我为了"方便"绕过工具的安全检查，就产出了一个假缺陷。**

---

## 规则（写下来以免重犯）

1. **验证服务器必须和 nginx 行为一致。** 不一致的验证服务器会说谎，
   而且说得比真相更有说服力。
2. **拦截模式锚定 origin。** `**/api/**` 会匹配 `/src/api/*.ts`。
3. **只用可见性感知的交互。** 不要用 `element.click()` 按坐标或下标点击；
   工具拒绝点击时，先问"它为什么拒绝"，而不是想办法绕过去。
4. **断言里带上 `content-type`。** 一个 JSON 接口返回 HTML 就是没到后端。
5. **出现"很严重"的结论时，先怀疑自己的工具。** 三次里有三次，
   破绽都是一个"对不上的细节"：
   - 接口返回 HTML
   - 公开路由也白屏
   - 隐藏按钮报错

---

## 三次之后仍然成立的真结论

这些是**修正工具之后**重新测出来的，可以相信：

| 结论 | 证据 |
| --- | --- |
| 生产构建在 `/pd-rehab/` 下正常运行 | 7 路由、0 个 404、0 个页面错误、正文长度与开发服务器逐一相同 |
| 后端不可达时应用**优雅降级** | 完整外壳、`—` 而非 `0`、明确提示文案、无技术细节泄露 |
| **页面按钮没有无效入口** | 8 个页面、16 个非破坏性按钮、**0 个无反应、0 个报错、0 个 4xx** |

最后一条正是本轮的目标。**用错工具时它报了 3 个问题；用对工具时是 0 个。**
