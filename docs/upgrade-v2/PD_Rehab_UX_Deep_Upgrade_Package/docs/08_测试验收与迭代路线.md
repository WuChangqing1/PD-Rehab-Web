# 08 · 分阶段开发、测试、屏幕截图与交付标准

## 阶段执行原则

每个阶段开始时 Harness 先 `git status`、记录现状；写计划、修改真实代码、跑现有测试+新增测试、进行浏览器操作验收、截图、提交 commit、更新 `docs/upgrade_report.md`。如果线上站点暂时访问不了，必须写“未验证”，不能声称通过。

### P0：审计与回归快照

- 读取本包及两份历史 Spec（如果仍在工作区），检查 current HEAD、Docker/systemd/Nginx、相关 API、角色兼容和媒体资源。
- 使用浏览器真实访问 `https://ccqspace.site/pd-rehab/`，从登录→工作台→评估→康复训练→随访逐页点击，并在浏览器调试中检查 Console、Network 404、Viewport 截图。如无法访问，先在本地启动前后端测试，必须清楚报告受限。
- 截图存项目 `docs/upgrade_screenshots/before/`，不得包含真实患者身份资料（用测试/去标识帐号）。
- 整理 `asset_gap_report.md`、`model_readiness_report.md`、`UX_issue_inventory.md`，先不更改数据库。

### P1：信息架构 + Visual Design System

- 五个主导航不变，工作人员功能统一，清理重复启动入口；评估和训练由其所属中心启动，模式内支持“推荐/全部/继续”，但同一个引擎。
- Card equal-height、统一封面比例、CTA底部对齐；移动端患者列表卡片；响应式表单/图表/Drawer；图片和文字异常宽度回归。
- `FollowUpPage` 真实可用时解除与路由的 `hidden` 语义冲突；功能测试仍隐藏。
- 可交付：设计 token、响应式截图、UI组件和 Playwright layout assertions。

### P2：芭蕾演示媒体完整闭环

- 经审核的安全动作 storyboard，至少两个可核实视频候选（Plié、Tendu）及对其它模式自录替代计划。
- Harness 下载可获授权片段，真实观看/审核时间码，生成 poster / silent-loop MP4，填写 `ballet_asset_manifest.json` 和版权鸣谢。
- 训练中心的5动作 static poster 等高卡；详情循环 video；Focus 中 demo/camera 双区，伴奏只有一个时钟，坐/站模式对应且无错位。
- 失败资源有明确回退，不产生破裂图片/404；未审核的变体禁用视频，不能用另一动作顶替。

### P3：钢琴训练深度

- 保留原五模式/自动三轮/Calibration，新增4类训练配方（SFT/CFT/双手同时/重音分组）；医生主界面不同时展示十几张功能卡。
- 增加事件 schema/metrics 版本/真实练习差异和后端记录；PC/手机手势输入回归；节拍和记录基于稳定时钟。
- 一次训练结束能从“随访与报告”追溯事件、练习配方、左右手指标。

### P4：微表情真实模型（可能阻塞）

- 缺 `weights+source+requirements+label map` 时只能做 adapter/schema/UI，状态为 BLOCKED，不能冒充完成。
- 真正获得后按模型前处理/检测→识别→推理→标准字段→数据库→可视化做 E2E；三个授权视频 case，模型路径不入 Public GitHub。

### P5：联调、性能、上线与回滚

- 前端和后端覆盖全部 flow：功能→患者→任务→结果→历史；模型/视频资源权限/超时错误；Nginx子路径刷新、移动浏览器硬件、服务器静态文件缓存与媒体可播放性。
- 部署前备份 DB/上传数据，评估兼容迁移，保留能一分钟切回的上个工作版本。不要停其它应用。

## 行为级验收场景

1. 工作人员选康复训练→钢琴→最近方案启动→选择患者→校准（需要时）→训练→自动轮次→结果→随访可见。
2. 工作人员选芭蕾→坐姿→Port de Bras→看到同动作坐姿封面与视频→开始→节拍+伴奏→录制/上传→分析→结果；切到站姿是对应站姿资源。
3. 工作人员选站姿扶椅→Demi-Plié→检查只有站姿→标准视频循环→质量不够返回修正建议，不产生伪分。
4. 评估中心→Finger Tapping 双手→保存→左右比较，旧算法不变；录像失败提醒友好。
5. 评估中心→面部分析，如果模型尚无权重，只显示不可用；取得真实模型后从真视频返回结果。
6. 手机打开同一路径，患者选择/退出焦点/安全确认、摄像头权限弹窗/上传回退、音频开始暂停正常。
7. 随访记录与训练 recipe、exercise mode、算法版本、数据 provenance 保持一致；没有数据不凭空画趋势。

## 必须运行的代码检查

- `python -m pytest`（在 backend 环境、实际路径执行），通过所有现有+新增单测。
- `npm test` 和 `npm run build`（frontend），无 TS errors。
- `ffprobe` 对所有 `APPROVED` 视频检查 codec、duration、分辨率、`-an`静音、可读；视频 <meta> mobile 浏览器能播放。
- 模型真实接入时检查同一视频稳定性，`_infer()` 不再显式占位；尚未提供时模型状态必须 NOT_CONFIGURED 而非 READY。
- 网络检查 `/pd-rehab/`, `/pd-rehab/training`, `/pd-rehab/assets/ballet/...mp4`, `/pd-rehab/api/...` 不混淆；鉴权和静态权限正确。

## 交付证据与停止条件

每轮回复必须：Git HEAD/branch、改动清单、测试命令和原始结果、真实浏览器截图路径、资产 manifest 状态、模型可用状态、阻塞清单、上线/未上线、回滚入口。严禁“全部完成”但视频没有下载、没有逐帧审核，或模型没有权重。
