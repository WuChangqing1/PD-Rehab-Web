# 02 · 面向工作人员 + 患者的产品信息架构与视觉系统

## 唯一主信息架构

```text
工作台     （摘要、最近操作、异常提示）
患者档案   （搜索、创建、编辑、只读病历与近期摘要）
评估中心   （综合评估 / 面部表现 / 双手 Finger Tapping）
康复训练   （钢琴训练 / 芭蕾训练；所有启动路径汇聚在这里）
随访与报告 （时间轴 / 指标趋势 / 报告；取消旧路由隐藏标记）
```

不新增管理员模块，不单列功能测试。已登录工作人员功能一致；患者没有账户，只在任务开始时使用 `PatientTaskLayout`。技术 API / 模型状态只用于运维，不是用户主菜单。

## “一个入口”的精确定义

- 用户从主导航进入**康复训练**；中心内可直接用两张一级大卡切到「钢琴」「芭蕾」，然后在同一训练上下文选择具体练习。
- 同类训练可以提供**多种启动方式**，但都属于同一个中心且汇聚到同一个真实训练会话：`按训练类型` / `按上次记录继续` / `按医生设置的推荐任务`。这些是**同一业务能力的入口变体**，不是三套不同实现。
- 同一练习打开后在一个工作区完成：患者选择→练习选择→演示与设置→开始→训练→结果；允许 Stepper 或 panel 切换，不意味着把所有步骤挤在一屏。
- 患者详情只看患者资料/摘要；工作台仅摘要，不再重复放十几个「开始训练」按钮。历史由随访统一负责。

## 两种工作状态

### A. 工作人员模式（控制与复核）

进入中心 → 选择训练 → 搜索/确认患者 → 选择目标与模式/座椅支持 → 查看介绍/短视频 → 开始任务 → 训练后复核结果。

### B. 患者任务模式（执行）

全屏、简化菜单；突出画面、节奏、指令、暂停、结束。退出任务需说明已保存进度和未保存内容；不允许默默变更患者；训练进行中禁止覆盖别人的 session。

## 康复训练中心交互蓝图

```text
康复训练                                                   患者：[选择/更换]
────────────────────────────────────────────────────────────────────────
[钢琴节奏训练                                  ] [芭蕾动作训练                     ]
 手指运动 · 节奏与协调                           姿态 · 上下肢协调 · 伴奏
 进入钢琴                                      进入芭蕾
────────────────────────────────────────────────────────────────────────
最近训练 / 继续上次任务  [继续]  （同一个训练引擎，不创建第三套流程）
```

**选择钢琴后**：`训练推荐/全部练习/最近方案` 三种浏览方式（不是三种实现），练习分层、时长、难度与适用输入方式明确；如未完成基础测试自动先测，后续进入患者任务页。

**选择芭蕾后**：坐姿 / 站姿扶椅 → 动作卡（统一静态封面）→ 详情窗/工作区（右侧循环无声示范视频，左侧目的、操作、所需设备、简短注意）→ 选择重复次数和节奏（工作人员）→ 患者 Focus → 摄像头录像/上传 → 结果。

## 视觉方向：平静、干净、有品质的医疗运动产品

- 背景：#F5F7FB；纯白卡片 #FFFFFF；主文字 #182235；次要文字 #65758B；强调蓝 #306DD8；浅蓝强调 #EAF1FE；分割线 #E5EAF2；成功 #238768；警示 #B87420。禁止大面积渐变和荧光色。
- 字号：页面标题 26px/32px（手机22px）；模块标题20px/26px；正文16px；次要信息14px；患者指令18–24px；按钮至少44–48px高。
- 圆角：卡片 16px；输入 10px；视频 14px；按钮 10px。阴影只做层次，不超过轻阴影；避免随卡片颜色涂底。
- 桌面内容宽：max-width 1360px，居中留白；栅格间隙16/20/24px，采用设计 token。
- 桌面：Header+Sidebar 主导航；移动：Header+Drawer。移动宽 `<768px`，卡片 1 列；平板 2 列；宽桌面 2–3列；页面不得横向溢出。

## 卡片等高与对齐：必须通过自动化检查

卡片结构定为：媒体头（同等16:9）、标题行（保留2行高度）、说明（最多2或3行、保留空间）、属性行、`margin-top:auto` 的 CTA 行。不要让文本数量决定 CTA 的垂直坐标。

```css
.rehab-grid { display:grid; grid-template-columns: repeat(2,minmax(0,1fr)); gap:20px; align-items:stretch; }
.rehab-card { display:flex; flex-direction:column; min-width:0; height:100%; overflow:hidden; border-radius:16px; }
.rehab-card__media { width:100%; aspect-ratio:16/9; object-fit:cover; }
.rehab-card__body { display:flex; flex:1; flex-direction:column; padding:20px; }
.rehab-card__title { min-height:3.2em; display:-webkit-box; -webkit-line-clamp:2; -webkit-box-orient:vertical; overflow:hidden; }
.rehab-card__desc { min-height:4.5em; display:-webkit-box; -webkit-line-clamp:3; -webkit-box-orient:vertical; overflow:hidden; }
.rehab-card__footer { margin-top:auto; padding-top:18px; }
@media(max-width:767px){ .rehab-grid {grid-template-columns:minmax(0,1fr);gap:14px;} }
```

上面为效果目标；Harness 应按现有组件命名实现，不能无条件复制导致特异性冲突。**在同一行卡片中，图片顶/底、标题起始、CTA 顶部与卡片底边视觉对齐误差不应超过约2px。**不同层级的卡片不必强行统一高度。

## 动作卡、示范区、患者模式的媒体交互

- 卡片只显示静态 `poster.webp` / `poster.jpg`（来自已许可视频同一动作的清晰帧）；卡片网格永不自动播放视频。
- 选中动作后再加载 `<video muted loop playsinline preload="metadata">`；永不同时自动播放所有卡片视频。
- 视频上覆盖轻量动作名称、模式、暂停/继续和全屏（根据设备）；示范视频和摄像头必须明显标注“动作示范”与“您的动作”，避免误将演示视频当患者实时画面。
- 训练节拍/钢琴伴奏应由独立音频引擎在用户手势后启动，示范视频静音播放，不会产生两套不一致音乐。
- 按下“开始训练”后进入 Focus 状态；大屏2栏（演示约40%、实时摄像头约60%）、手机竖屏上下顺序（演示可缩成小窗）；未授权摄像头时回退视频上传。
- 重要任务步骤明确 `准备中/正在录制/正在分析/已完成/需要重试`，必须禁用重复提交。

## 结果设计与无结果设计

- 默认只呈现 3–5 项与当前动作相关的客观指标；动作的关节指标要按定义选，不能 Port de Bras、Tendu 都显示“抬肩角度”。
- 原始数据、质量控制、算法版本放“查看详细记录”；高级数据不删。
- 微表情真实模型未配置时，不显示虚拟彩色饼图；按钮不可用或明确“当前暂不可用”。
- 没有可靠时序数据时不显示“改善了 X%”；默认显示测量结果而不推断临床疗效。

## 响应式与无障碍

- 验证375/390/430/768/1024/1366/1440屏宽；小屏不横向溢出。
- iOS 输入字号≥16px、防自动放大；`getUserMedia` 需要安全上下文（HTTPS/localhost）；`video playsinline`；音频点击启动；支持竖/横屏。
- 患者触控面积≥44×44，按钮不靠颜色单独标识；错误与完成状态文字清楚；主 CTA 一屏可见。
- 偏好减少动画 (`prefers-reduced-motion`) 时减弱卡片位移动效；示范视频仍允许由用户控制。

## 文案清理

移除普通界面的 Demo/科研/Phase/模型路径/虚拟等工程字样；但**安全操作提示不能删**，如“不适请停止训练”“请扶稳固定椅子”。演示数据内部标记保持，不对公众声称其为真实临床观测。对术语采用医生可理解的中文，患者主流程只保留简短操作提示。
