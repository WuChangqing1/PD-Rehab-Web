# 03 · 芭蕾动作训练 V2：动作、示范视频和交互定义

## 理念与证据边界

PPT 第3页讨论芭蕾/舞蹈干预研究，指出平衡、姿态、节奏、协调及非运动症状等研究方向；其中 PD-Ballet 为试验方案而非本平台验证过的疗效。公开 PD-Ballet 研究方案说明了**专业人员指导、坐姿或站姿热身、音乐与节奏、下肢移动和因人调整**，而不是推荐患者独自在家做标准专业芭蕾动作：https://link.springer.com/article/10.1186/s12906-023-04296-y 。本网站应被设计为**由工作人员选择训练内容、协助患者执行的辅助训练界面**。

## 当前真实代码衔接

动作 key 保持：`BALLET_PORT_DE_BRAS`, `BALLET_FIRST_POSITION`, `BALLET_TENDU`, `BALLET_DEMI_PLIE`, `BALLET_WEIGHT_SHIFT`。以 `backend/app/ml/pose/exercises.py` 为唯一权威来源；新增演示素材时通过 `exercise_key + execution_mode + demonstration_version` 关联。历史 Yoga session 仍按原名称和原指标保存。不要更改旧 ID 伪称新动作。

## 动作定义与安全适配矩阵

| Key | 对用户显示 | 坐姿 | 站姿扶椅 | 重点观察 | 视频的必须条件 |
|---|---|---|---|---|---|
| `BALLET_PORT_DE_BRAS` | 芭蕾手臂组合 | ✓ | ✓ | 肩/肘角度、左右协调、节律 | 双臂从准备位→抬起→外开→回位；正面上肢无遮挡 |
| `BALLET_FIRST_POSITION` | 第一位姿态保持（简化） | ✓，为坐姿上身改编 | ✓ | 躯干倾斜、稳定、保持时长 | 不强制双足极端外旋；坐姿版不要用纯站姿视频冒充 |
| `BALLET_TENDU` | 伸腿点地 | ✓，为坐姿伸膝/脚尖触地改编 | ✓ | 髋膝踝范围、左右对称、次数 | 站姿必须有固定支撑；一条腿向前/侧舒适伸出再回收 |
| `BALLET_DEMI_PLIE` | 扶椅浅屈膝 | ✗（当前代码不支持） | ✓ | 双膝屈曲、稳定、次数 | 清晰示范小范围屈膝，脚自然朝向；不可深蹲/跳跃 |
| `BALLET_WEIGHT_SHIFT` | 节奏性重心转移与手臂配合 | ✓，为坐姿躯干左右移动 | ✓ | 躯干左右倾、双侧协调、节奏 | 镜头能看到躯干/髋部；站姿有稳定支撑 |

**关键医疗可用性限制**：视频来源中的标准 `first position`、`plié` 可能演示极大足外旋与深屈膝；不得直接让 PD 患者照做。必须裁出安全的浅范围段，并由老师/专业指导者审核；无合格素材则该模式暂不启用视频，明确标记“待审核”，可先使用正确制作的静态分解示意，不能假称是循环真人视频。

## 统一动作卡设计

静态卡片：同样16:9封面、中文名、英文名（次要）、坐姿/扶椅标签、约1句任务目的、时长/次数（来自真实定义）、按钮“查看动作”。所有卡片 `display:flex` 等高、底部按钮对齐。若某坐姿版未审核，禁用该变体而不是展示不一致的站姿动作。

## 视频脚本与剪辑要求（实际执行前核对画面）

每个 exercise/mode 一个**真正对应动作**的示范条目；要求一个完整循环（起始稳定姿态→动作→恢复起始姿态），通常 4–12 秒，时长需以真实视频为准而非硬裁。镜头稳定、身体关键关节可见、简单背景、无遮挡；不可用花哨转场遮挡膝/髋/肩。封面从视频中抽取能看清动作的代表帧，不直接拿其他舞者照片。手机走低码率 MP4/H.264，另可 WebM。源音轨去掉以免和伴奏冲突。

### 5 组动作 cue storyboard（建议版本，须人工确认）

**A Port de Bras，坐/站**

- 准备：头部正直、躯干稳、双肩放松，双臂自然放于身前。
- 1–4拍：双臂缓慢向前上方抬至舒适高度。
- 5–8拍：舒适范围向外打开。
- 9–12拍：双臂缓慢回到准备位。
- 正确关注：肩左右角度差、运动轨迹，不能以越高越好评价。

**B 第一位姿态保持，模式不同**

- 坐姿：坐稳、双足平放、躯干伸直，双臂形成舒适圆弧；不要求脚做芭蕾第一位。
- 站姿扶椅：双脚与髋约同宽、自然舒适外旋或平行，靠椅支撑、躯干正直。
- 1–4拍调整姿态；5–12拍稳稳保持；4拍回位。
- 判定：躯干前后/左右偏移和有效观察时长；单摄像头2D位姿无法证明重心稳定，禁止写“重心稳定评分”而无验证传感器。

**C Tendu，坐/站**

- 站：固定支撑，左/右脚缓慢沿地面向前小范围伸出，脚尖轻触地面并回收；避免跨步/转身。
- 坐：伸膝—脚尖触地—回收，命名“坐姿伸腿改编版”，不等于标准 Tendu。
- 1–4拍伸出，5–6拍短暂停，7–10拍收回，11–12拍准备下一次。
- 必须保证侧面或略侧面能看到髋、膝、踝，避免裙装遮挡关键点。

**D Demi-Plié（只站姿扶椅）**

- 手扶固定椅背，两脚舒适自然站立，双膝小角度屈曲后缓慢伸直；不要求双脚180°外旋。
- 1–4拍轻微下沉，5–8拍回起；禁止跳跃、深蹲或突然起身。
- 用双膝角度/左右协调、重复次数、帧质量衡量；不提供不可靠的“医学风险评分”。

**E 节奏性重心转移+Port de Bras**

- 坐：躯干小幅左右移动配合双臂，坐稳；站：扶椅、缓慢小幅左右转移。
- 1–4拍右，5–8拍回中；9–12拍左，13–16拍回中；视频完整一循环。
- 单目 Pose 能量化躯干横向倾斜，但不能精确测量压力中心、跌倒风险；不声称真实动态平衡测量。

## 训练状态机

`PICK_PATIENT → PICK_MODE → PICK_EXERCISE → PREVIEW_LOOP → READY → COUNTDOWN → CAPTURING → UPLOADING → ANALYZING → RESULT → DONE/RETRY`。

- `PREVIEW_LOOP` 仅播放示范；不可把示范文件送去模型计算患者 Pose。
- `COUNTDOWN` 和 `CAPTURING` 使用同一 monotonic clock 与节拍引擎；一个 start/stop 生命周期。
- `CAPTURING` 中录视频且采集时间戳；动作次数由真实视频与可解释定义计算，而不是 UI 节拍次数。
- `FAILED_QUALITY` 展示可执行纠正建议（“请让双脚进入画面”），保留失败日志，不产生有效运动指标。
- 进入 RESULT 时默认医生模式；患者只看完成信息。

## 数据保存

`pose_sessions` 保留原字段，新增时仅做可回滚迁移：`exercise_definition_version`, `execution_mode`, `demo_asset_id`, `demo_asset_version`, `guidance_bpm`, `source_video_file_id`, `recording_duration`, `quality_flags`, `pose_model_version`。历史不改写。示范视频源和患者录像严格隔离，禁止测试时混存。

## 节奏与影像对齐

音频引擎以单独 `AudioContext` 的时间轴安排 tick，视频视觉示范可循环、可暂停。不得把播放中视频当前时间直接用作患者姿态时间戳；示范相位漂移时可在拍组边界柔性重新对齐，不硬跳视频帧。音频需点击用户手势后开始，切页必须停止音频和 Camera tracks。
