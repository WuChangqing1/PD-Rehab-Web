# 05 · 钢琴节奏训练深化方案（保留现有模式 + 训练配方）

## 已有能力

`frontend/src/piano/session.ts` 已定义：基础能力测试 `CALIBRATION`；四个核心训练 `SINGLE_KEY_RHYTHM`,`ALTERNATING_HANDS`,`MAPPED_SEQUENCE`,`FOLLOW_THE_BEAT`；可选 `MEMORY_RHYTHM`。`PianoTrainingPage.vue` 有整套轮次/训练功能，`piano/difficulty.ts` 有自适应难度逻辑。**不要重复实现这五个 mode，也不要让用户从几乎相同的功能卡里猜区别**。

PPT 第4页提出音乐/节律线索、SFT 同步、CFT 撤除提示后自主保持节奏、即时多通道反馈，以及逐步任务复杂度。这些是**扩展设计参考**，不是对每位 PD 患者都适用的强制频率或强制 110–120% 节奏升级治疗处方。

## 新的信息架构

```text
康复训练 > 钢琴节奏训练
    ├─ 推荐开始（保留上一次的训练配置并检查有无基线）
    ├─ 基础节奏      [单键 / 听提示同步 / 撤提示续奏]
    ├─ 双手协调      [交替 / 同步 / 简单双手分工]
    └─ 进阶练习      [序列 / 分组重音 / 跟拍 / 可选记忆]
```

列表是训练**配方/模板**，不能把每种配方都新增一个重复顶级页面。所有训练均进入同一个 `PianoTrainingPage`/`PatientTaskLayout`，复用既有 `PianoKeyboard`, `useRunner`, `pianoApi` 和事件结构。

## 新增配方（建议首版 4 个）

| ID | 用户名 | 类型 | 操作 | 目标行为数据 |
|---|---|---|---|---|
| `SFT_CUE_SYNC` | 听提示按键 | 复用 `SINGLE_KEY_RHYTHM`/`FOLLOW_THE_BEAT` | 系统每1/1.5/2s给可视+听觉 cue，按提示按下指定键 | 反应延迟、命中率、节拍误差、缺失率 |
| `CFT_RHYTHM_HOLD` | 保持节奏 | 新增「提示→撤除」状态但复用音符引擎 | 前 4~8拍听提示，之后无 cue 继续等间隔按键 | 无提示阶段的平均绝对节拍误差、持续时间、间隔CV |
| `BIMANUAL_SYNC` | 双手同时敲击 | 新增双事件归并/一对多 cue | 左右键同时目标，兼容手机左右分区 | 双手同步误差、命中率、左右不平衡 |
| `ACCENT_GROUPING` | 强弱节拍分组 | 扩展节奏模板 | 4拍一组、第一拍强调，手跟随音符提示 | 组内早晚误差、强拍命中率、miss rate |

## 可选延伸配方（P2，须先稳定上述功能）

- `TEMPO_SWITCH`：慢—中—慢的可控速度变化，记录每段准确率与适应时间；不无限加速。
- `CALL_AND_RESPONSE`：系统演奏短动机，患者复现，与现有 `MEMORY_RHYTHM` 合并而非另造相同功能。
- `HAND_SELECTIVE_CUE`：颜色/音色区分左右手，简单规则切换。不要冠以疾病认知诊断名称。
- `STEPWISE_SEQUENCE`：2音→3音→4音的短序列递进，沿用 `MAPPED_SEQUENCE` 事件格式。

## 统一训练配置与安全护栏

医生只需要选“练习卡 / 偏好手侧 / 训练时长 / 低中高强度（可选）”；系统根据个人基线决定具体 BPM/节拍窗口/序列长度。不能向患者展示算法参数输入框；可在医生高级设置中修改并记录。没有可靠 Calibration 时先启动 30–60 秒基础能力测试；已有基线则允许“按上次方案开始”。训练停止、暂停、重复和重试都必须保留 session 状态与原始事件。

## 原始事件与可解释指标

- 保留 event `cue_onset_time_ms`, `target_time_ms`, `actual_time_ms`, `response_latency_ms`, `timing_error_ms`, `key_down/up_time_ms`, `hold_duration_ms`, `hand`, `finger_hint`, `is_correct`, `is_missed`。
- 区分：`response_latency_ms = first_valid_response - cue_onset`；`timing_error_ms = actual - target`（负提前、正延后）；`timing_MAE = mean(abs(error))`。请勿把误差当成反应延迟。
- CFT 在 cue 撤除后并无实际 `cue_onset`：对应反应延迟应为 `null`，不能以目标时间硬补；仍有目标拍位可算 timing error。
- 同步任务需包含 cue 对应两个手键、两次实际 keydown，存 `inter_hand_onset_diff_ms = |left_ms-right_ms|`；不能随便用现有“一个 cue 一按键”计算作为双手同步分数。
- signed timing-error mean 可接近0；别直接用 `std/signed_mean` 产生无意义 CV；主要稳定性应使用事件间隔 CV、timing MAE/SD、分手数据与个人历史。
- 触屏只知道触摸哪个琴键，不知道实际是哪根生理手指；`finger_hint` 是映射提示，不能呈现为真实指级评估。

## 训练体验

- 每张练习卡：图标/模式名/一句具体目标/建议长度/左右手标签/CTA 对齐。
- 真正进入训练：简短一次示范→3秒准备→清楚节拍和琴键→真实触摸/按键→及时“正确/过早/过晚/漏按”反馈→本轮完成→下一轮（如果是三轮流程）→查看医生结果。
- PC 支持键盘、鼠标；移动设备使用 Pointer Events 和足够大区域，避免一次7个键装不下时变超小琴键。
- 模式分组和配方必须显示出明显不同的交互和数据差异，不只是换标题。
- 节拍引擎使用单一时钟与预定计划，避免 setTimeout 漂移；音频自动播放在用户交互后 `AudioContext.resume()`。
- 结果统一显示准确率、节拍偏差、持续表现、双手差异；进一步折叠显示 Raw Events/metrics。

## 自适应逻辑

沿用 `piano/difficulty.ts` 规则，在没有医生确认前不要把 PPT 的“100→110→120%”当成统一处方。可为 SFT/CFT/同步任务编写**新的配方能力边界**，例如节奏减慢、目标密度减少、增加休息或单手模式，但每轮只改1–2个主变量，并写入 `difficulty_change_reason`。错误多时不自动“加大难度”。

## 测试

- CFT 撤提示时间点正确、没有 cue 的事件 latency 为 null。
- 双手同步输入同时按下容差、左右手异步事件保存无丢失。
- AudioContext 暂停/返回关闭，禁止后台双重音频。
- 当前五个原模式 + 新配方同一患者数据被正确区分；报告不混算不同训练协议。
- 手机触摸相同 key 可以按下/抬起（PointerUp/Cancel/离开时释放），失焦不会“卡琴键”。
- 自动三轮流程保留，用户不能跳轮；Memory Rhythm 继续是可选而非强制。
