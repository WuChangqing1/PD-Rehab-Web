# 01 · 基于 `PD-Rehab-Web-main(3).zip` 的源码审计

## 审计口径

本次阅读并检查了 ZIP 的项目目录及重点文件。此为**静态源码审计**，不能替代真实登录、模型推理、摄像头权限和服务器 E2E 浏览器验证。生产链接 `https://ccqspace.site/pd-rehab/` 在本次访问尝试中不可抓取；仓库 `docs/images` 中存在历史页面截图，但可能与线上实时版不同。

### 指标与算法审计重点

- `backend/app/ml/micro_expression/adapter.py` 明确不推理：没有可用模型。**不得展示 PPT 模型分数为真实预测**。
- `backend/app/ml/pose/exercises.py` 只定义了动作、韵律、目标次数、支持模式和原始指标，当前部分展示分数 formula 为空：先用可解释原始运动量，再设计临床专家确认的规则。不能随机生成 0–100。
- 当前 `BALLET_TENDU` 同时支持 seated 和 supported standing，坐姿变体不等同真实 ballet tendu，应显示“坐姿适配版”且记录独立规范。
- `BALLET_DEMI_PLIE` 只支持 `STANDING_SUPPORTED`，不能因为 UI 想统一而强行开放坐姿版。
- `FIRST_POSITION` 的传统足外旋不能强制 PD 用户转到 180°；应接受自然舒适足位并明确“简化姿态练习”。
- `frontend/src/piano/session.ts` 已有 `MEMORY_RHYTHM`，不要再次增加“记忆节奏2”重复功能。
- `frontend/src/pages/MovementTrainingPage.vue` 约800+行、`PianoTrainingPage.vue` 约1100+行：建议拆成步骤子组件与 composables，避免把视觉补丁堆进单个超长文件。

### 本轮不应做的事

- 新增管理员、角色管理、MRI、微服务、Redis/Celery、后台自训练模型。
- 删除数据库原始记录；混淆旧 Yoga 历史和新 Ballet 标签。
- 让系统自动依据 PPT 的 110%–120% 直接提升所有患者难度或安排固定临床周期；这些只是研究场景，不是适用于所有患者的治疗处方。
- 在公开视频里暗示被拍摄者患有帕金森病，或把未经审核的普通芭蕾动作当康复处方。
