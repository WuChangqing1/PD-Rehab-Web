# 06 · 微表情模型落地：PPT事实、资源缺口与集成验收

## PPT 支持什么、不支持什么

- 第1页：论文涉及 **FG-LGL（Flow-Guided Local-Global Representation）微表情识别**，包含光流引导双注意力/ViT-DA、9个AU语义区域、两级Transformer，以及 **AUG-GCN（AU-Guided Graph Convolutional Network）微表情检测**，结合滑窗累积光流、鼻尖运动补偿、AU先验图卷积、BATEM onset/apex/offset。PPT展示论文实验结果 UF1/UAR/F1，这是**原论文报告结果**，不是此网站在 PD 患者数据上的实际准确率。
- 第2页：论文系统采用 Vue3 / Python+PyTorch / MySQL 分层，流程为登录→采集→对齐→微表情检测→识别→结果展示→记录管理。可以指导前后端数据链路。
- 但 PPT **没有提供**源码、预训练 checkpoint、标签索引、依赖锁、采集要求、输入 FPS/尺寸、真实测试视频和使用许可。上传的 ZIP `backend/app/ml/micro_expression/adapter.py::_infer` 依然显式拒绝推理，代码**尚未真正接入 PPT 所述模型**。

## 资源确认门槛（逐项有证据才视为已就绪）

1. 源码目录与可执行入口：FG-LGL、AUG-GCN 是否都提供？是否是同一实际作者可公开复用的代码？
2. 训练权重文件、文件 SHA256、标签映射表、训练/预处理超参。
3. 对应环境版本（Python、PyTorch、CUDA、OpenCV、MMCV等），第三方版权/协议。
4. 视频格式、分辨率、最短/最长时长、FPS、正侧脸与光照要求、面部对齐和采样策略。
5. 两模型是串联（先 spotting 再 recognition）还是已有一体化推理工程？禁止凭 PPT 猜接口。
6. 输入质量不佳（找不到脸、光流失败、无有效 apex）的真实错误模型。
7. 输出是 detection segments、情绪标签百分比分布、每片段类别、还是 PD 二分类概率？**真实模型没有就不显示**。
8. 用户/团队是否授权将模型部署到公网可用服务器？检查模型权重不可进入 Public GitHub。

## 推荐结构（在真实源码确认后实施）

```text
MicroExpressionService
   ├── preprocess(video) -> normalized_face_frames
   ├── spotting_adapter (AUG-GCN if actually available) -> segments[onset,apex,offset,confidence]
   ├── recognition_adapter (FG-LGL if actually available) -> per_segment_label_scores
   ├── aggregate_results (only from genuine observations)
   └── persistence/reports + job status
```

不要求两模型一次全部就绪：若 spotting 缺失，仅有 recognition 且其输入已验证，可以用真实、经过规则说明的手工裁切片段试运行，但不能宣称自动检测已经完成；如果模型都缺失，保留正常产品不可用状态。不能用 MediaPipe Face Landmarker 的 blendshape 输出伪称 FG-LGL 检测结果。

### 数据契约示例（nullable、实际不保证这些值）

```json
{
  "assessment_session_id": "UUID",
  "model_status": "READY",
  "pipeline": {"spotting_model":"AUG-GCN","recognition_model":"FG-LGL"},
  "model_version": "actual-checkpoint-sha",
  "input_quality": {"face_detected_ratio": 0.93, "fps": 30},
  "segments": [{"onset_ms": 1000, "apex_ms": 1350, "offset_ms": 1700,
                "label": "name-from-real-model", "confidence": 0.81}],
  "tag_distribution": null,
  "pd_probability": null,
  "inference_time_ms": 0,
  "source_type": "MODEL_INFERENCE"

```

以上是**接口形态示范**，不是模型真实输出，数字为占位说明，不允许写进 demo 结果后声称是推理结论。若模型只给片段类别，不要自行制造全片情绪百分比，除非聚合方法已明确并审计。

## UI 设计

入口固定 `评估中心 → 面部表现分析 → 选择患者 → 录视频/上传 → 分析中 → 结果`。结果显示两层：

- 面向工作人员：`本次可用面部片段数量`、`时间轴上检测到的微动作事件`、`每段的模型分类或标签分布`（仅实际返回），下方包含质量提示、未识别片段、可见的原始视频播放定位。
- 面向患者：简单采集指导和完成状态，不显示复杂预测图。

真实权重缺失时页面提示“面部分析暂不可用”，不能随机绘制 7 类情绪百分比。PPT 的原研究实验结果放 `docs/references/` 或技术说明，**不能展示为平台性能**。

## 安全与性能

- 私有权重存 `/opt/pd-rehab/models/micro-expression/`（实际路径按服务器权限调整），配置 `MICRO_EXPRESSION_MODEL_DIR`；Public GitHub 和日志不得公开模型/患者视频。
- 录像存储 UUID 路径，访问须认证及患者权限上下文。输出与 session 绑定，禁止 patientId/sessionId 不一致。
- 模型单例加载，GPU 推理单并发或容量受控；长任务 PENDING/RUNNING/SUCCESS/FAILED；超时可取消，API 返回真实失败原因。
- 输出保留 model/source/algorithm version、推理时间、质量元数据和原始结果 JSON。演示数据保留 provenance，不冒充真实模型。

## 模型验收最低标准

- 至少3段经权利人授权并可重复测试的视频：有微表情片段、无检测到的微表情片段、低质量片段；验证正常/空/失败三类状态。
- 真实模型 `load()` 成功 + checkpoint hash 可追溯 + 推理调用成功；对同一视频重复推理能在容差内一致。
- 逐段可定位起止时间；有分类就显示真实标签；无二分类 PD probability 就必须保持 null。
- UI 不得把脸部情绪标签自动转换成疾病严重度、诊断概率或康复成效百分比。
- `pytest` 模型 schema/失败路径 + 后端实测日志 + 前端截图 + 数据库存储证据。

## 仍需用户提供的实际资产（不能凭空生成）

老师模型的 **源码、权重、requirements、标签表、推理示例及授权范围**。只有拿到这些后，Harness 才能让 PPT 上的模型成为生产可用功能。
