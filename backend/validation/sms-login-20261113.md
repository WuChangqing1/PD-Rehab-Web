## 审计结论与接口

短信提供方通过固定 HTTPS POST 访问 PNVS；RFC3986 参数排序和编码、POST 根路径、AccessKeySecret 加 `&` 后 HMAC-SHA1/Base64 的签名与官方规则一致。含中文固定签名向量、POST 参数及错误响应由离线测试覆盖。请求不包含 URL 上的手机号/验证码，不跟随重定向、不自动重试、不记录提供方请求/响应；API 只返回脱敏号码。短信由阿里云生成，设置数字六位、300 秒有效、旧码覆盖、60 秒间隔、`ReturnVerifyCode=false`、`AutoRetry=0`。仅 `Model.VerifyResult=PASS` 才认证成功。

官方参考：[发送](https://help.aliyun.com/en/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)、[核验](https://help.aliyun.com/en/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)、[RPC 签名](https://help.aliyun.com/en/sdk/product-overview/rpc-mechanism)。以上为接口/源码审计，真实 RAM 授权和网络发送/核验仍待经授权的测试号码验收。

所有以下路径加 `/api/mobile/auth`；公网现有前缀为 `/pd-rehab/api/mobile/auth`：

| 方法/后缀 | 合同 |
| --- | --- |
| GET `/providers` | 公开开关，短信开启后 sms=true、wechat=false、wechat_app_id 为空；不返回密钥 |
| POST `/sms/challenge` | `{phone}`，11 位中国手机号或 +86；返回 challenge_id、expires_in=300、retry_after=60、phone_hint |
| POST `/sms/login` | `{challenge_id,code,sync_consent_version:"account-sync-v1"}`；code 六位数字；返回原双 Token、PATIENT/患者身份；仅首建账号返回 recovery_code |
| GET `/identities` | 当前移动账号 Bearer，只返回本人脱敏绑定列表 |
| POST `/identities/sms/challenge` | 当前移动账号 Bearer + `{phone}`；要求登录会话建立未满 15 分钟 |
| POST `/identities/sms/bind` | 同一会话 Bearer + `{challenge_id,code}`；要求新鲜会话；绑定不更换患者编号、不新发身份 |

已审阅并测试：服务未配置时关闭；发送配额在网络前提交，失败也占额度；同手机号每60秒1次/24小时10次、IP每小时20次、全服务每24小时默认100次（首次请求起固定窗口）；挑战用途、会话、过期、五次核验上限、单次使用和并发竞争；绑定冲突不合并账户；首次登录只创建 PATIENT 并复用原同步/恢复码/会话机制；旧密码登录、刷新、撤销与患者授权继续通过回归。

错误合同：登录 proof 错误401；绑定 proof 错误400（不触发客户端刷新/退出）；绑定会话过旧403；已有绑定冲突409；未配置/提供方不可用503；频控429附 Retry-After。微信实现保留，生产必须 `MOBILE_WECHAT_ENABLED=false`。
